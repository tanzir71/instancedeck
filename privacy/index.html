Privacy

Your profiles stay on your PC

No analytics, no InstanceDeck account and no credential reading.

Desktop data

InstanceDeck stores its own profile names, IDs, paths, colors, preferences and launch logs locally. Profiles default to %LOCALAPPDATA%\InstanceDeck\Profiles; you can choose another root. Settings and metadata updates retain backups. Backups and sign-in stashes are never automatically pruned.

The launcher uses process metadata and file metadata to discover apps, track profiles and identify supported data layouts. It never reads, parses, decrypts or transmits app cookies, authentication files, session tokens or DPAPI blobs.

Your target apps have their own privacy policies and network activity. InstanceDeck’s local-only design does not change those apps’ behavior.

Diagnostics are local

Diagnostics show InstanceDeck’s launch settings, discovered app versions, process status and structured launcher logs. They do not include target app file contents. You can redact paths before copying a report. Review a report before posting it publicly.

Network activity

InstanceDeck has no telemetry or background analytics. Its only network feature is the user-enabled update check against this project’s GitHub release feed and the update download you explicitly confirm. No update request is made before first-run consent or while the preference is disabled. Windows packages are unsigned; updater integrity signatures do not establish Windows publisher trust. There is no public update feed while the first release remains a draft.

This website

The site uses local assets and has no third-party analytics, advertising scripts or tracking cookies. It is hosted on GitHub Pages; GitHub processes hosting requests under its privacy statement. External links, including downloads and sign-in pages, are subject to their hosts’ policies.

Questions

Contact the maintainer through the project repository. Do not post credentials or private app data in an issue. See Security for reporting a vulnerability.
