# Local builds and publishing

The maintainer selected local verification and Git pushes. Project workflows are
manual-only; GitHub does not run Node/Rust builds or tests on a normal push.
GitHub Pages deploys the prebuilt files from gh-pages with `.nojekyll`.

Run verification on Windows:

```powershell
pnpm i
pnpm typecheck
pnpm lint
pnpm test
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
```

Build release packages from the exact committed version/tag. ARM64 compilation
also needs the Visual Studio ARM64 C++ tools and libraries:

```powershell
rustup target add x86_64-pc-windows-msvc aarch64-pc-windows-msvc
$env:RELEASE_TAG = 'v0.1.0'
node scripts/check-release-version.mjs
pnpm tokens
pnpm --filter @instancedeck/desktop tauri build --target x86_64-pc-windows-msvc --bundles nsis --ci
cargo build --release --locked -p ideck-cli --target x86_64-pc-windows-msvc
./scripts/package-release.ps1 -Target x86_64-pc-windows-msvc -Architecture x64 -Version 0.1.0
pnpm --filter @instancedeck/desktop tauri build --target aarch64-pc-windows-msvc --bundles nsis --ci
cargo build --release --locked -p ideck-cli --target aarch64-pc-windows-msvc
./scripts/package-release.ps1 -Target aarch64-pc-windows-msvc -Architecture arm64 -Version 0.1.0
```

Retain/rename an existing dist/release-x64 or dist/release-arm64 directory
before packaging again. The packager refuses to overwrite an existing output
directory. Compilation does not execute an installer or certify real
accounts/hardware.

Stage both package directories' files in a new dist/release-artifacts directory,
then run `node scripts/create-draft-release.mjs` with RELEASE_TAG set. It checks
the reports against the existing tag. Finalize with the local integrity key as
described in [the release process](releases.md). v0.1.0's original architecture
builds came from the successful tagged workflow; the exact downloaded packages,
signatures, versions and tamper rejection were verified locally before release.

Build, audit and push the static website:

```powershell
pnpm publish:site
```

This builds Astro and Storybook locally, packages/audits their footer, paths,
flat CSS and dark preview, then pushes an isolated gh-pages commit. It retains
branch history and all local staging directories, uses no force push, and sets
Pages to that prebuilt branch. Git preserves the generated bytes so CSP hashes
remain valid. Source code stays on main. Re-run after publishing a release so
Download and Changelog use actual public metadata.

The optional manual Pages workflow deploys only if SITE_ACTIONS_DEPLOY_ENABLED
is explicitly enabled and Pages is configured for workflow deployment. The
default delivery path is the local command above.
