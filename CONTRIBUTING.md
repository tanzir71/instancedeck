# Contributing

Read [AGENTS.md](AGENTS.md), [HANDOVER.md](HANDOVER.md),
[DECISIONS.md](DECISIONS.md) and [PROGRESS.md](PROGRESS.md) first. Figma/design
exports and generated tokens govern visual changes. Keep desktop and site
components in `packages/ui`, with stories for each new state. Use flat colors,
no shadows or drawn vendor logos.

Use Node 24, the pinned pnpm version, Rust 1.97 and Windows build tools.

```powershell
pnpm i
pnpm typecheck
pnpm lint
pnpm test
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
pnpm build:desktop
```

Rust tests export frontend bindings; commit intentional generated changes.
Recipe schema is generated by `cargo run -p ideck-cli -- recipe-schema`.
Validate new recipes with fakes and Unicode/space paths before doing manual app
QA. Record real versions, OS, evidence and limitations. Community is the default
until the full manual matrix passes; a launched process does not prove account
isolation.

Never inspect credentials, patch/copy target app binaries, hard-delete user
data, inject into another process or add telemetry. Test sign-in/recovery with
synthetic fixtures. Do not run a real account flow or close a user's main app
without the specified consent. Keep retained stashes/backups. Report
vulnerabilities privately as described in [SECURITY.md](SECURITY.md).

Keep PRs focused. Explain the user-visible behavior, why it changed, automated
validation and any deferred manual checks. Do not claim a check was performed
without evidence. See [release instructions](docs/releases.md) for packaging; no
trusted Windows signing certificate is required or used.
